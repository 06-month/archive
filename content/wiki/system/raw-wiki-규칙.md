# raw-wiki-규칙 (vault 헌법)

`/ingest`·`/query`·`/lint`가 런타임에 참조하는 결정 규칙. **추상 표현 금지 — if-else 트리와 수치 표만.**

---

## A. 진입 결정 트리 (4리프)

> [!danger] Q0. 출처 위치 게이트 (가장 먼저, 예외 없음)
> **파일이 `raw/` 안에 있나?**
> - 아니오 (`Zotero/` 등 다른 폴더) → **즉시 ingest 거부.** 위키에 한 글자도 반영하지 않는다. "raw/로 옮겨 달라"고 안내만. (사용자 절대 지시 2026-06-13)
> - 예 → Q1로 진행.
>
> 이 게이트는 도메인 적합성(Q1)보다 **우선**한다. `Zotero/`는 도메인이 맞아도 ingest 금지.

> [!important] Q0.5. 멱등성 가드 (Q0 다음, raw 본문 읽기 **전**)
> **이 raw가 이미 ingest됐나?** — `wiki/log.md`의 `## [..] ingest` 엔트리 + wiki 노트들의 `sources:` frontmatter를 grep해 raw 파일명을 찾는다.
> - **이미 있음** → **Q0.6(동일성 확인)으로 진행.** 바로 skip하지 않는다.
> - **처음 봄** → Q1로 진행.
>
> 목적: 같은 raw를 재처리해 토큰을 중복 지불하는 일 방지. 비용 큰 "본문 읽기"보다 **앞에서** 차단한다.

> [!warning] Q0.6. 동일성 확인 (Q0.5에서 "이미 있음"일 때만, 저비용)
> **파일명이 같다고 같은 자료가 아니다.** 파일명 매칭만 믿지 말고 **헤더 ~30줄만 읽어** 실제 동일 자료인지 확인한다(전체 통독 아님 — 비용 최소).
> - 대조 항목: **제목 · arXiv ID · 저자 · `created` 날짜 · 줄 수**. 기존 source-meta 노트의 서지와 비교.
> - **일치** → 기존대로 **skip.** "이미 [날짜] ingest됨"만 보고.
> - **불일치(= 동명이 자료로 교체됨)** → **처음 보는 raw로 간주**하고 Q1로 진행. 기존 박제분의 철회 여부를 사용자에게 확인.
>
> 근거: 2026-07-27 `raw/OmniX.md`가 동명이 논문(파노라마 → 4D 궤적장)으로 교체됐으나 파일명 grep이 "처리됨"으로 오판. 파일명은 **키가 아니라 힌트**다.

```
자료를 받으면 (Q0·Q0.5·Q0.6 통과 = raw/ 내부 + 미처리(또는 교체된) 파일만):
├─ Q1. 도메인(전공 수업 / 3D Vision 연구)과 관련 있나?
│   ├─ 아니오 ─────────────────────────────────→ [반려]
│   └─ 예 ↓
├─ Q2. 정제할 핵심 정보 밀도가 충분한가?
│       (요약·개념·엔티티로 박제할 가치가 있나)
│   ├─ 예, 충분 ───────────────────────────────→ [통과]
│   ├─ 주변적/저밀도 (한두 줄짜리 언급) ────────→ [참조]
│   └─ 판단 어려움 / 영역 불명 ─────────────────→ [모호] (§D)
```

- **[통과]**: full ingest. sources 노트 + 영향받는 개념/엔티티 노트 갱신 + index + log.
- **[참조]**: `wiki/index.md`에 1줄 + 최소 stub 노트(있으면). 깊은 정제 안 함.
- **[모호]**: §D 절차. 사용자 선택 전까지 wiki 미반영.
- **[반려]**: wiki에 넣지 않음. `log.md`에 `반려` 사유만 1줄 기록.

## B. 영역 분류 결정 트리 (4분기)

```
[통과]·[참조] 자료의 영역:
├─ ① 학과 수업(강의·과제·시험·교재)에서 나온 자료?
│        → wiki/courses/{과목}/
├─ ② 3D Vision / 3DGS / NeRF / Scene Reconstruction 논문·연구 자료?
│        → wiki/research/
├─ ③ 특정 과목·연구에 종속되지 않는 일반 수학·CS 개념?
│     (예: 선형대수, 군론/Lie group, 확률, 최적화, 해시함수)
│        → wiki/concepts/
└─ ④ 위 어디에도 명확히 안 맞음
         → [모호] (§D, 사용자 개입)
```

> 승격 규칙: 처음엔 ①/②에 두되, 다른 영역에서도 재등장하면 ③ concepts로 옮기고 원위치엔 링크만 남긴다.

## C. 압축 룰

| 항목 | 룰 |
|---|---|
| **읽기 범위** | ingest 대상 raw는 **전체 통독** (선택/표적 읽기 금지 — 누락 방지) |
| 압축률 | raw 1000줄 → wiki 100~200줄 (10~20%) |
| 노트 길이 상한 | 200줄 — 넘으면 분리 |
| 직접 인용 | raw 1자료당 ≤ 3줄 |
| Cross-link 최소 | 3개 — 그중 다른 영역 ≥ 1개 |

> 읽기는 전체, 출력(wiki)은 압축. 둘은 별개다 — 다 읽되 10~20%로 정제한다. 토큰 절약은 Q0.5·Q0.6(이미 처리한 **동일** raw skip)로만.

## D. 모호 처리

## E. 우선권 주장 표기 (SOTA·최초)

논문은 자기 시점·자기 벤치마크에서 "최초/SOTA"를 주장한다. 이를 **그대로 옮기면 후속 논문 노트와 충돌**한다(위키는 여러 시점을 동시에 담으므로).

| 상황 | 표기 룰 |
|---|---|
| "**최초**(first)" 주장 | `저자 주장` 명시 + **범위 한정어** 필수 — (무엇의 최초인지 + 기준 연월) |
| "**SOTA**" 주장 | **벤치마크·서브셋 명시** + 연도. "SOTA"만 단독 사용 금지 |
| 같은 territory에 선·후행 노트 존재 | 양쪽에 **상호 링크** + 범위가 어떻게 다른지 1줄 |
| 실제로 갱신된 경우(후속이 능가) | 선행 노트에 "후속 〈후속노트 위키링크〉가 갱신" 1줄 추가 (선행 노트만 읽는 독자 보호) |

> 판정: 범위·시점이 다르면 **모순 아님** → 범위 명시로 해소. 범위·시점이 같은데 결과가 다르면 **진짜 모순** → `> [!warning] 모순` 콜아웃 + 양쪽 출처.
>
