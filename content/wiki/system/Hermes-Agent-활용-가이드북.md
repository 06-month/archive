# Hermes Agent 활용 가이드북

이 문서는 “내가 Hermes Agent를 가지고 무엇을 할 수 있나?”에 대한 실전 메뉴판이다. 이 vault에서는 [[raw-wiki-규칙]]을 따르며, 특히 `/ingest`는 `raw/` 내부 자료만 대상으로 한다.

---

## 1. 한 줄 정의

Hermes Agent는 단순 챗봇이 아니라 **파일·터미널·브라우저·이미지·일정·기억·스킬을 써서 실제 작업을 수행하는 에이전트**다. 대화로 지시하면 내가 필요한 자료를 찾고, 파일을 만들거나 고치고, 명령을 실행해 결과를 검증한 뒤 보고한다.

---

## 2. 바로 시킬 수 있는 일

### A. 이 Obsidian wiki 운영
- `raw/`에 넣은 강의자료·논문을 `/ingest` 규칙에 맞춰 한국어 wiki 노트로 정제한다.
- `wiki/index.md`를 카탈로그처럼 갱신하고, `wiki/log.md`에 작업 이력을 남긴다.
- `/query` 스타일로 wiki만 읽어 답변을 합성한다. raw를 직접 다시 읽지 않는 것이 원칙이다.
- `/lint` 스타일로 고립 노트, 미해결 링크, 모순, 데이터 갭을 진단한다.

예시 프롬프트:
- “raw/새논문.md ingest 해줘.”
- “DUSt3R 계보를 wiki 기준으로 요약해줘.”
- “전체 wiki lint 해서 고립 노트와 데이터 갭 알려줘.”

### B. 코드·프로젝트 작업
- 저장소 구조를 읽고 관련 파일을 추적한 뒤 버그 수정, 기능 추가, 리팩터링, 테스트 실행을 한다.
- Python/Node/GitHub/터미널 작업을 실제 명령으로 검증한다.
- PR 리뷰, 이슈 정리, CI 실패 원인 분석 같은 개발 워크플로를 보조한다.

예시 프롬프트:
- “이 에러 로그 기준으로 원인 찾아서 고쳐줘.”
- “테스트 먼저 추가하고 기능 구현해줘.”
- “최근 diff 리뷰해서 위험한 부분만 짚어줘.”

### C. 조사·요약·학습 보조
- 웹 문서, 논문 메타데이터, 기존 wiki 노트를 바탕으로 개념 지도를 만든다.
- 영어 자료를 한국어로 압축하고, 기존 노트와 교차링크한다.
- “무엇을 먼저 공부할지” 로드맵이나 체크리스트를 작성한다.

예시 프롬프트:
- “3DGS를 NeRF와 비교해서 초심자용으로 설명해줘.”
- “내 wiki 기준으로 feed-forward GS 연구 계보를 학습 순서로 바꿔줘.”
- “이 주제에서 아직 raw가 없는 핵심 논문 후보를 찾아줘.”

### D. 문서·콘텐츠 제작
- Markdown 문서, 블로그 초안, 발표 개요, 표, 체크리스트를 만든다.
- 기존 글의 톤을 유지하면서 더 간결하게 고친다.
- 다이어그램, SVG/HTML 목업, 이미지 생성 프롬프트도 만들 수 있다.

예시 프롬프트:
- “이 노트를 블로그 글 목차로 바꿔줘.”
- “발표 10분짜리 대본과 슬라이드 구조를 만들어줘.”
- “이 개념 관계를 다이어그램으로 만들어줘.”

### E. 자동화·리마인더·반복 작업
- 반복 점검, 정기 요약, 피드 모니터링 같은 일을 cron job으로 예약할 수 있다.
- 단, 현재 TUI 세션에서 만든 cron 기본 출력은 이 채팅으로 실시간 배달되지 않고 로컬에 저장된다. 알림을 원하면 Telegram 등 gateway 전달 대상을 명시해야 한다.

예시 프롬프트:
- “매주 월요일 오전 9시에 이번 주 연구 TODO를 물어보는 작업 만들어줘.”
- “2시간마다 특정 페이지가 바뀌었는지 확인하고 바뀌면 Telegram으로 알려줘.”

## 3. 내가 쓰는 핵심 도구 감각

| 범주 | 할 수 있는 일 |
|---|---|
| 파일 | 노트 읽기·검색·생성·패치, wiki 구조 관리 |
| 터미널 | 테스트·빌드·git·패키지 명령 실행, 시스템 상태 확인 |
| 브라우저/웹 | 웹페이지 열람, 동적 페이지 상호작용, 콘솔 오류 확인 |
| 이미지/음성 | 이미지 분석·생성, 텍스트 음성화 |
| 세션 검색 | 과거 대화에서 결정사항과 맥락 찾기 |
| 메모리 | 장기적으로 유효한 사용자 선호·환경 사실 저장 |
| 스킬 | 반복 workflow를 절차 문서로 저장해 다음 작업에 재사용 |
| 하위 에이전트 | 독립 조사·코드리뷰처럼 병렬 작업 분담 |
| cron | 일정 기반 반복 작업 자동 실행 |

## 4. 좋은 지시법

1. **목표를 먼저 말하기**: “무엇을 만들지/고칠지/판단할지”를 첫 문장에 둔다.
2. **입력 위치를 주기**: 파일명, 폴더, URL, raw 경로를 명시한다.
3. **완료 기준을 주기**: “테스트 통과”, “200줄 이하 노트”, “index/log 갱신”처럼 끝 조건을 말한다.
4. **금지사항을 말하기**: “본문은 고치지 말고 링크만”, “커밋하지 마”, “raw 밖은 읽지 마”처럼 경계를 준다.
5. **원하는 출력 형태를 지정하기**: 표, 체크리스트, 요약, 새 note, 패치, 발표안 등.

좋은 예:
> `raw/논문A.md`를 전체 통독해서 research 노트로 ingest 해줘. 노트는 200줄 이하, 한국어, [[3D-Gaussian-Splatting]]·[[DUSt3R]]와 비교 링크를 넣고 index/log도 갱신해줘.

---

## 5. 이 vault에서 특히 유용한 명령 패턴

- **새 자료 박제**: “`raw/파일명.md` ingest 해줘.”
- **wiki 기반 질문**: “wiki만 근거로 X와 Y를 비교해줘.”
- **건강 진단**: “전체 wiki lint 해줘. 자동 수정은 하지 말고 권고만.”
- **블로그 연결**: “본문 수정 없이 이 blog 글 끝에 관련 wiki 링크만 붙여줘.”
- **학습 로드맵**: “현재 index 기준으로 3D Vision 입문 순서를 만들어줘.”
- **작업 재개**: “지난번에 X 어디까지 했는지 찾아서 이어서 해줘.”

---

## 6. 한계와 안전장치

- 모르는 파일·현재 상태·날짜·시스템 정보는 추측하지 않고 도구로 확인해야 한다.
- `.env`·토큰·비밀번호 같은 비밀은 사용자가 명시하지 않으면 읽거나 출력하지 않는다.
- 파괴적 명령, 커밋·푸시·히스토리 변경은 명시 요청 없이는 하지 않는다.
- `raw/` 밖 자료는 이 vault의 `/ingest` 대상이 아니다. 필요하면 먼저 사용자가 `raw/`로 옮긴다.
- 메모리는 오래 유지될 사실만 저장한다. 일회성 진행상황은 [[log]]나 세션 기록으로 남긴다.

## 7. 처음 써볼 추천 요청 10개

1. “이 vault의 구조를 읽고 내가 뭘 공부 중인지 요약해줘.”
2. “wiki/index.md 기준으로 연구 계보를 Mermaid 다이어그램으로 정리해줘.”
3. “raw/새논문.md를 ingest 해줘.”
4. “최근 log를 보고 다음에 ingest하면 좋은 후보를 골라줘.”
5. “3DGS와 NeRF의 차이를 wiki 근거로 설명해줘.”
6. “내가 쓴 블로그 초안을 더 자연스러운 한국어로 다듬어줘.”
7. “이 코드 에러를 재현하고 최소 수정으로 고쳐줘.”
8. “이번 주 공부 계획을 5일치 체크리스트로 만들어줘.”
9. “이 이미지/스크린샷을 분석해서 문제점을 찾아줘.”
10. “이 반복 작업을 cron으로 예약해줘. 알림은 Telegram으로 보내줘.”
