## 핵심 takeaway
1. **2D flow matching(Flux.1-dev) 재활용**: 파노라마 **생성·인지·완성**을 하나의 생성 패러다임으로 통합. RGB→X 인지 + masked X→X 완성. → [[OmniX]]
2. **기하 + PBR 재질 인지**: 기존 2D-lifting이 외형만 생성한 것과 달리 distance·normal + albedo·roughness·metallic까지 → **PBR-레디·relighting·시뮬 가능 3D 장면**.
3. **Circular Synchronization**(학습 불필요): spatial operator를 circular translation-equivariant로 만들어 ERP seam 근본 해결(circular padding + token padding·attention masking).
4. **Separate-Adapter**: 모달리티별 LoRA 배정으로 cross-modal 인지 최고 성능 + 확장 유연.
5. **PanoX**: UE5 합성 다중모달 파노라마(실내5+실외3, >10K 인스턴스/60K 이미지) — 실내외+조밀 기하·재질 주석 최초 파노라마 데이터셋.

## 후속 질문
- 파노라마 2D-lifting(OmniX, mesh+PBR) vs 파노라마 GS([[3D-Gaussian-Splatting]] 계열 DreamScene360 등) — 그래픽스 통합·편집성 대비 렌더 품질 trade-off?
- 생성 prior 재활용 인지(OmniX) vs feed-forward 복원([[VGGT-Ω]]) — 단일 파노라마 기하 정확도에서 어느 쪽이 우위이고 왜 상보적인가?
- distance 예측 부정확 → bumpy 표면 문제: feed-forward 깊이 모델(MoGe·VGGT-Ω)을 인지 단계에 결합하면 해소되나?
- metallic 일반화 취약(PBR 데이터 희소) — 합성 PanoX 확장 vs 실사 PBR 캡처 중 무엇이 병목 해소에 결정적?
- concepts 갭 후보: **flow matching / rectified flow**, **inverse rendering·PBR**, **LoRA** — 현재 concepts 페이지 없음(향후 ingest 시 신설 검토).
